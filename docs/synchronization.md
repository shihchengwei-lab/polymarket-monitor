# 訂單簿同步與失效處理

## 如何判讀 Ready

- **Ready** 表示最近一次從 Gamma 核定的完整清單中，所有子市場仍開放，而且每個市場的 YES 和 NO 簿都已同步。Gamma 回報清單不再符合監控條件、任一子市場結算或任一簿失效時，群組立即停用總和與補數檢核。Gamma 暫時查詢失敗時，仍健康的連線可繼續顯示上次核定的群組，畫面會標示查詢失敗。
- 有最佳買價和最佳賣價時，兩者的平均為中間價。總和是各子市場 YES 的中間價相加，補數偏差是該市場的 YES 與 NO 中間價相加再減 1。缺少任一邊報價時，受影響的數值顯示 `—`。
- 每次畫面更新都取自同一份本機群組狀態。各市場的報價可能來自交易所不同時間點。

- **QuotesReady** 表示 Augmented NegRisk 事件的具名、已啟用選項均已同步。名冊排除未啟用的預留選項及 Other。這些報價無法構成完整整籃，因此停用整籃計算和紙上交易。終端的 `watch --once` 仍會在首個已同步的報價畫面寫入成功後結束。

## 同步行為

- Gamma 以事件 slug 提供完整的子市場清單、condition ID、YES/NO Token ID 與新連線使用的初始價格變動單位。持續模式在 Gamma 確認事件終止後，等末畫面寫入並 flush 才成功退出，等候超過 5 秒會回報失敗。若目前所有子市場都關閉而事件仍開放，會繼續查找新市場。WebSocket 確認的結算在本次監控期間持續生效。每個群組最多記錄 4,096 個已結算市場；第 4,097 個不同市場結算時停止監控並回報容量錯誤，帳本截止取該幀受理時間與先前行情缺口中較早者，紙上帳戶仍可對帳。
- Token 依序從 `Disconnected`、`Syncing` 進入 `Synced`。初始連線中斷會取消同步，回到 `Disconnected`。已同步的簿失效時進入 `Stale` 並清空報價，重新連線後從完整快照重建。
- 增量使本機買一大於或等於賣一時，若同筆官方買一低於賣一，該 Token 進入 `Reconciling` 並隱藏報價，整組暫停開倉。500 ms 內恢復正常雙邊價差即可沿用原連線。期限自首次異常起算；逾時或交叉時缺少有效官方價差，立即使訂閱失效並依退避重建。
- 以同一 WebSocket 的完整快照銜接後續增量，同毫秒訊息按收到的順序套用。若某 Token 的增量先於首張快照抵達，或首張快照驗證完成時已達 15 秒期限，只隔離該 Token。其他 Token 在退避期間繼續更新，群組維持 `NotReady`。持續模式先等 15 秒再重建訂閱，未恢復時等待時間逐次倍增至 60 秒。全部開放 Token 重新同步後，退避回到 15 秒。
- 連線中的價格變動單位由 WebSocket 更新。REST 週期核對完整價位與數量，差異只供診斷。
- 隔離恢復到期時，若 Gamma 清單已過期，會保留健康連線並繼續更新報價，直到 Gamma 重新核定清單才重建訂閱。
- WebSocket 每 10 秒送出心跳，20 秒內未收到文字 `PONG` 即斷線。應用層心跳或協定 Pong 等待寫入時，連線仍受理可讀的行情。若寫入達到預算或原心跳期限，按既有規則封存並重連。行情以成功入列的本機時刻排序。每次確認第一個 PING 寫出前先登記期限；若回報仍需等待則撤回暫定期限，成功則保留。執行緒在這次輪詢內停頓時，以輪詢開始時計算期限，可能提早降級。行情入列、空佇列取時與封存共用這個期限；即使接收執行緒晚醒，仍按原期限截斷。Gamma 查詢完成後至少隔 30 秒才發出下次查詢。首次暫時查詢失敗時，持續模式顯示 `NotReady` 並依原時程重試。連線故障依退避重試，距上次成功核定 Gamma 清單未滿 30 秒時可直接重用。所有新訂閱都在本機送出前確認清單仍有效，過期時先重新核定。

`watch` 的心跳與終端輸出各自執行。輸出堵塞時，最多保留一份待寫畫面。行情等待佇列最多 64 則、合計 16 MiB，滿載時會使整條訂閱失效並重連。Gamma 事件與清單的單次回應限制為 4 MiB，CLOB REST 簿回應限制為 1 MiB。每則行情最多 8 MiB、4,096 個事件，每個快照或增量事件最多 16,384 筆原始更新，同一價位重複出現也逐筆計數。單本簿最多保留 4,096 個非零價位，超限時隔離該 Token。

封存輸入與替換待寫畫面共用同一次鎖定；已被輸出端取走的畫面可完成寫入。換線時，程式先以 `NotReady` 替換待寫畫面，每幀在整幀語意驗證通過後才依序發布行情與成交；公開成交須符合 0 < 價格 < 1 且股數為正。若驗證期間已達鎖盤期限，即使該幀包含結算也保留原截止。依原順序處理缺口前已受理的行情，遇到首個壞幀後僅採認可辨識的結算，最後發布更新後的畫面。`--once` 首次達到 `Ready` 時封存訂閱，依序處理已接收的行情後才決定是否輸出。若封存前曾因佇列滿載拒收行情，這次訂閱無法回報成功。終端寫入端已取走畫面但未在期限內確認時，指令會回報失敗，終端可能已收到部分或全部內容。

監控在排空已受理的資料後、通知帳本前裁決停止。這時收到停止，會依原切點結束訂單。若帳本先收到中斷並已送出撤單，之後停止仍沿用該撤單的期限。接受 Gamma 關場時，若沒有現役或待退役的輸入，帳本以接受關場的時刻結束訂單。若仍有訂閱，即使佇列為空，也由封存流程決定關場時刻。監控等到最後畫面寫入完成才返回。終端機寫入或刷新失敗時，正在寫入、已排隊和之後提交的確認都會收到同一筆原始 I/O 錯誤。

## 程式庫接入

程式庫用 `group.refresh_discovery(&client, base, ttl)` 查詢並套用 Gamma 名冊。每個群組同時只保留一筆查詢。用 `tokio::select!` 同時等行情與查詢，行情先到可立即處理，下次呼叫會沿用原請求的端點與有效期。若關場或結算容量終止已提交，取消等待只會中止這次呼叫。再次查詢會繼續等待同一筆撤單回執，並取得先前尚未交付的結果。要放棄未完成的 HTTP 請求或改用其他端點，先呼叫 `cancel_gamma_refresh()`。查詢失敗或名冊已過期時保留原核准期限。

用 `open_input` 取得本次訂閱識別碼，呼叫 `admit_raw` 或 `admit_event` 入列，再用 `advance_input` 依序處理。入列時記錄本機接收時間。換名冊、呼叫 `close_input` 或遇到整批行情錯誤時，群組先處理缺口前已受理的行情，再撤銷紙上報價並讀完已受理的結算。若關場與壞幀同時發生，非同步入口會先完成已受理的本機撤單回執，再回報原始錯誤。若封存時另有傳輸故障，完整錯誤鏈會保留兩個原因。結算容量用盡仍可按錯誤型別辨識。舊識別碼送來的資料會回傳 `Ok(false)`。即使沒有收到訊息，也要以 `snapshot_deadline()` 和 `reconciliation_deadline()` 中最早的期限排定喚醒並呼叫 `advance_input(source)`。首照到期會隔離該 Token；空佇列以取樣所得的本機時刻裁決。若取樣時已達交叉恢復期限，該次呼叫即封存輸入、保留已受理結算並回傳錯誤，可重新呼叫 `open_input()`。

當本機佇列仍有行情待處理，`group.paper()` 會拒絕依行情新增的委託與策略轉單，回傳 `StaleSignal`。依序推進輸入後可重新取得報價。同一訂閱短暫失去 Ready 時暫停新單，健康腿仍依實際掛量增減更新深度，保留原排位與已消耗股數。處理時已過期的合法深度仍依序更新公開掛量，以原受理時刻判斷能否成交。既有委託仍可查詢、撤單或對帳。500 ms 恢復期限以實際提交時刻判定；若排程延誤，仍先依入列順序計入缺口前的健康腿成交。

程式庫同步入口遇到結算容量用盡時立即回報錯誤。撤單已到期，帳本依原生效時刻釋款；尚未到期，群組保留同一筆回執。同步呼叫端可用 `receipt_deadline()` 取得期限，到期後呼叫 `advance_receipt()` 完成並發布一次。提早推進會得到 `Ok(false)`。`receipt_complete()` 只查詢結果。若沒有呼叫者推進，最後發布的帳本仍顯示凍結；丟棄群組會放棄未完成的回執。Cockpit 監控與 Gamma 關場會自行等待並推進，瀏覽器無須輪詢。
